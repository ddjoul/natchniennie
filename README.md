# пра.бел

**пра.бел** — беларускі культурна-асветніцкі праект: студэнцкія вершы, пераклады, матэрыялы пра культуру і беларускую мову.

на сайце можна чытаць творы, знаёміцца з аўтарамі і пакідаць каментарыі. інтэрфейс пераважна на беларускай мове.

## раздзелы сайта

- **галоўная** — агульная стужка апублікаваных матэрыялаў.
- **вершы** — вершы з пошукам, фільтрамі і сартаваннем.
- **пераклады** — пераклады з пазначэннем аўтара арыгіналу і мовы арыгіналу.
- **культура** — навіны і матэрыялы пра культуру і мову.
- **аўтары** — спіс аўтараў і спасылкі на іх профілі.

кожны аўтар мае асобную старонку з фатаграфіяй, біяграфіяй, цытатай, сацыяльнымі сеткамі, вершамі і перакладамі. кожны твор адкрываецца на асобнай старонцы.

## магчымасці

- загрузка матэрыялаў і аўтараў з Supabase;
- пошук па назвах, тэкстах і аўтарах;
- сартаванне па даце, назве або аўтары;
- фільтраванне твораў па аўтары і мове/правапісе;
- спасылкі на аўтараў паводле ніка, калі запоўнена поле `nickname`, або UUID;
- даты рымскімі лічбамі з падказкай у звычайным фармаце;
- каментарыі пад вершамі і перакладамі з папярэдняй мадэрацыяй;
- адаптыўнае афармленне;
- выявы кнопак меню з падкрэсліваннем пры навядзенні і ў выбранага раздзела;
- уласны PNG-курсор і індыкатар загрузкі.

## афармленне

асноўны шрыфт — Tektur. палітра:

| колер | значэнне |
| --- | --- |
| белы | `#ffffff` |
| шэры | `#616161` |
| чорны | `#000000` |

карткі матэрыялаў маюць аднолькавы памер і чаргуюць колеры. на шырокім экране рады размешчаны са зрухам; на невялікіх экранах сетка перабудоўваецца.

## тэхналогіі

- HTML, CSS і JavaScript;
- Supabase: PostgreSQL, Data API і Storage;
- GitHub Pages для публікацыі сайта;
- Google Fonts для загрузкі Tektur.

```text
.

├── culture.html            # культура
├── authors.html            # спіс аўтараў

├── post.html               # асобны твор
```

SQL-файлы наладжвання базы і моўнага фільтра могуць захоўвацца ў рэпазіторыі асобна. іх трэба выконваць праз SQL Editor Supabase, а не падключаць да HTML.

## лакальны запуск

калі ўсталяваны Python, запусці ў папцы праекта:

```bash
python -m http.server 8000
```

адкрый `http://localhost:8000`.

для загрузкі даных, бібліятэкі Supabase і вэб-шрыфту патрэбны інтэрнэт. зборшчык не выкарыстоўваецца.

## наладжванне Supabase

у `config.js` пазнач налады свайго праекта:

```js
window.PRA_CONFIG = {
  url: 'https://your-project.supabase.co',
  publishableKey: 'your-publishable-key'
};
```

у браўзерным кодзе выкарыстоўваецца толькі публічны `publishable key`. пароль базы, `service_role` і сакрэтныя ключы нельга дадаваць у файлы сайта або рэпазіторый.

### табліцы

#### `authors`

- `id` — UUID аўтара;
- `name` — імя або псеўданім;
- `nickname` — унікальны нік для спасылкі, неабавязковае поле;
- `bio` — біяграфія;
- `quote` — цытата;
- `avatar_path` — поўны HTTPS-адрас фатаграфіі;
- `instagram_url`, `tiktok_url`, `telegram_url` — спасылкі на сацыяльныя сеткі.

калі падключаны `profile-layout.js`, першы радок `bio` вылучаецца як кароткая інфармацыя пры наяўнасці пераносу радка:

```text
г. Віцебск, БДУ, 21 год
кароткая біяграфія аўтара…
```

#### `posts`

- `id` — UUID публікацыі;
- `author_id` — спасылка на `authors.id`;
- `title`, `body` — загаловак і поўны тэкст;
- `category` — тып публікацыі;
- `status` — статус публікацыі;
- `created_at`, `published_at` — даты;
- `original_author`, `original_language` — звесткі пра арыгінал перакладу;
- `language_code` — мова/правапіс апублікаванага тэксту.

катэгорыі: `poem`, `translation`, `news`, `culture`, `language`, `idea`.

сайт паказвае толькі запісы са статусам `published`. значэнне павінна быць без прабелаў і пераносаў радка.

для перакладаў `author_id` паказвае на перакладчыка, а аўтар арыгіналу запісваецца асобна ў `original_author`.

| `language_code` | варыянт |
| --- | --- |
| `bel_classic` | бел (кл.) |
| `bel_official` | бел (аф.) |
| `bel_latin` | бел (лац.) |
| `ru` | рус |
| `pl` | пол |
| `en` | англ |

запісы без мовы паказваюцца ў рэжыме «усе мовы». калі слупок `language_code` адсутнічае, моўны фільтр адключаецца.

#### `comments`

- `id` — UUID каментарыя;
- `post_id` — спасылка на твор;
- `display_name` — імя, пазначанае наведвальнікам;
- `body` — тэкст каментарыя;
- `status` — `pending`, `published` або `rejected`;
- `created_at` — дата адпраўкі.

### правы доступу

для працы праекта павінны быць наладжаны правы табліц і RLS:

- публічнае чытанне звестак пра аўтараў, прызначаных для сайта;
- чытанне толькі апублікаваных публікацый;
- чытанне толькі ўхваленых каментарыяў да даступных твораў;
- адпраўка каментарыяў толькі са статусам `pending`;
- адсутнасць у наведвальнікаў правоў на змяненне і выдаленне запісаў або самастойнае ўхваленне каментарыяў.

фільтры ў JavaScript не замяняюць серверныя палітыкі доступу. не захоўвай непублічныя даныя ў табліцы аўтараў, даступнай наведвальнікам.

## публікацыя матэрыялаў

матэрыялы дадаюцца праз панэль Supabase. публічнай формы адпраўкі вершаў у бягучай версіі няма.

1. ствары аўтара або выберы існага.
2. дадай запіс у `posts` і пазнач яго `author_id`.
3. запоўні загаловак, тэкст, катэгорыю, мову і дату публікацыі.
4. усталюй `status = published`.
5. абнаві старонку сайта.

для фатаграфій аўтараў загрузі файл у публічны bucket Supabase Storage і ўстаў поўны публічны URL у `avatar_path`.

## мадэрацыя каментарыяў

каментарыі адпраўляюцца ў `comments` са статусам `pending`.

у Supabase → Table Editor → `comments`:

- выберы запісы з `status = pending`;
- правер тэкст;
- усталюй `published` для публікацыі або `rejected` для адхілення.

пасля абнаўлення старонкі ўхвалены каментарый адлюстроўваецца пад творам. імя наведвальніка не пацвярджаецца. апавяшчэнні ў Telegram або па пошце і асобная панэль мадэратара пакуль не падключаны.

## выявы меню і курсор

калі ў `app.js` уключана пераключэнне кнопак на SVG, патрэбны файлы:

```text
images/nav-home.svg
images/nav-poems.svg
images/nav-translations.svg
images/nav-culture.svg
images/nav-authors.svg
```

SVG трэба экспартаваць з зыходнага макета. альтэрнатыўны варыянт — PNG высокай раздзяляльнасці пад ранейшымі назвамі з захаваннем CSS-памераў адлюстравання.

для замены курсора выкарыстоўвай `images/cursor.png`. каардынаты актыўнага пункта задаюцца ў пераменнай `--cursor` у `styles.css`. тэкставыя палі захоўваюць тэкставы курсор.

## GitHub Pages

1. загрузі файлы ў рэпазіторый, захаваўшы структуру папак.
2. адкрый Settings → Pages.
3. выберы публікацыю з галіны і папку, у якой знаходзіцца `index.html`.
4. дачакайся публікацыі і адкрый спасылку, паказаную GitHub.

для ўласнай `404.html`, якая павінна працаваць і па глыбокіх неісных адрасах, пазнач у яе `<head>` рэальны корань сайта перад адноснымі спасылкамі:

```html
<base href="/repository-name/">
```

для каранёвага сайта або ўласнага дамена выкарыстоўвай `/`. не дадавай прыклад з `repository-name` без замены на свой шлях.

## абмежаванні бяспекі

каментарыі маюць папярэднюю мадэрацыю, але бягучая версія не змяшчае сервернай CAPTCHA і паўнавартаснага абмежавання частаты адпраўкі. поле-пастка ў форме не абараняе ад прамых запытаў да API.

перад шырокай публікацыяй рэкамендуецца прымаць каментарыі праз серверную функцыю з праверкай CAPTCHA і абмежаваннем частаты, закрыўшы прамую ананімную ўстаўку ў табліцу.

правярай усе дзейныя палітыкі RLS, захоўвай рэзервовыя копіі і абараняй акаўнты кіравання праектам. публічны рэпазіторый або хаванне зыходнага кода самі па сабе не вызначаюць бяспеку базы.
