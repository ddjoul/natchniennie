пра.бел — обновлённый сайт

что изменено
• 01 галоўная, 02 вершы, 03 пераклады, 04 пра_культуру, 05 пра_аўтараў.
• author.html?id=UUID — отдельный профиль из базы: фото слева, имя/биография/цитата справа, соцсети под фото, произведения ниже.
• post.html?id=UUID — отдельная страница произведения из базы, с комментариями для стихов и переводов.
• равные карточки: белая / чёрная / серая.
• Manrope для интерфейса, Cormorant Garamond для заголовков и стихов.
• gif-логотип в images/logo.gif; можно заменить своей гифкой. статичный вариант logo.png для режима уменьшения движения.
• подписи в нижнем регистре. имена и произведения отображаются как записаны в базе, без изменения регистра.

порядок установки
1. сделайте резервную копию базы и текущих файлов.
2. откройте migration.sql и выполните его в SQL Editor Supabase. миграция рассчитана на таблицы authors и posts из нашей предыдущей версии с UUID id, author_id, body, category, status, created_at, published_at. если структура другая, не запускайте без адаптации.
3. замените файлы сайта файлами архива. config.js уже содержит ваш адрес проекта и publishable key из переписки. секретных ключей в нём быть не должно.
4. старые data.js и script.js не используются: HTML подключает config.js и app.js. удалите старые подключения.
5. опубликуйте в GitHub Pages и обновите страницу. SQL миграцию нужно выполнить до открытия нового сайта.

поля authors
name — имя и фамилия в одном поле (как хотите показывать).
bio — краткая информация, обычный текст.
quote — цитата или несколько цитат, разделённых переносами строк.
avatar_path — полный HTTPS URL доступной фотографии (например, URL публичного файла Supabase Storage), не внутренний путь бакета.
instagram_url — https://www.instagram.com/имя/
tiktok_url — https://www.tiktok.com/@имя
telegram_url — https://t.me/имя
все записи authors публичны, не храните здесь личные данные, которые не должны быть доступны посетителям.

поля posts
category: poem / translation / news / culture / language / idea.
status: draft или published. сайт показывает только published.
author_id: id автора профиля. для translation это переводчик, его профиль и содержит этот перевод.
original_author: имя автора оригинала перевода.
original_language: язык оригинала.
body: текст, переносы строк сохраняются.

комментарии
новая таблица comments. посетитель без регистрации отправляет имя и текст, запись получает pending. имя самозаявленное, не подтверждённое.
в Table Editor проверяйте pending и меняйте status на published (или rejected). после обновления страницы одобренный комментарий появляется под произведением.
посетителям не разрешено менять status, created_at или редактировать/удалять записи. insert не запрашивает возврат строки, поскольку pending скрыт политикой чтения.
старая форма публикации стихов не возвращена; форма предназначена только для комментариев.

важно перед широкой публикацией
эта версия комментариев с премодерацией, но без серверного ограничения частоты и CAPTCHA. скрытое поле-ловушка не защищает от прямых запросов к API. для публичного сайта с большим трафиком добавьте Edge Function с CAPTCHA и серверным rate limiting, а прямую анонимную вставку в comments запретите. премодерация предотвращает автоматический показ спама, но не заполнение базы спамом.
миграция не удаляет сторонние политики RLS, созданные вручную: проверьте, что другие политики не разрешают чтение черновиков/неодобренных комментариев или произвольную запись.
таблица comments создаётся новой; если она уже существует с другой структурой, нужна адаптация.

запуск локально
в папке сайта: python -m http.server 8000
откройте http://localhost:8000
шрифты и библиотека загружаются через интернет. если Google Fonts недоступен, используются системные шрифты.
проверки: профиль автора без текстов, профиль с переводом, отдельный стих, отправка pending, публикация комментария в панели, черновики недоступны, телефон.
